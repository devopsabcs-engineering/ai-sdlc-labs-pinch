# ADR-001: Use symmetric locale catalogs and `Intl`

- **Status:** Accepted
- **Date:** 2026-10-06

## Context

Pinch must ship complete English and French UI, accessible names, sample content, persisted locale,
document language, and locale-aware numbers. It must also work offline without a framework or
translation service.

## Decision

Keep `en` and `fr` locale catalogs with the same nested key shape. A small typed translator resolves
keys and interpolation values; `Intl.NumberFormat` handles decimal separators. Set `<html lang>`
whenever locale changes, and store the locale in preferences. Bilingual recipe content uses explicit
`en`/`fr` fields rather than UI catalog keys.

A repository script flattens both catalogs and fails the `i18n-parity` gate for missing, extra, or
empty keys. Unit symbols and canonical stored numbers are not translated. Tests cover interpolation,
locale switching, `lang`, number formatting, and catalog parity.

## Consequences

- All shipped strings remain local, reviewable, and available offline.
- Key drift is detected before merge, while French copy can differ naturally in length.
- Adding a locale requires a complete catalog and localized sample content.
- This is intentionally smaller than adopting a runtime i18n dependency for two locales.
